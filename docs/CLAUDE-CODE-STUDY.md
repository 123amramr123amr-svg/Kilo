# دراسة: Claude Code مقابل AURA — الفكرة، الملفات، المهارات، والمقارنة الصادقة

> بحث أُجري في نوفمبر 2026 من المصادر الأصلية: مستودعات Anthropic على GitHub
> (`claude-code`, `skills`, `claude-plugins-official`)، وثائق `code.claude.com`،
> `agentskills.io` (معيار المهارات)، سجل التغييرات (CHANGELOG حتى الإصدار **2.1.322**)،
> وقضايا المستخدمين على GitHub + مراجعات مجتمعية.
> الهدف: نعرف إيه اللي ناقصنا فعلاً، مش نقلّد شكل حد تاني.

---

## 1. الخلاصة في ست سطور

1. **Claude Code مش «شات بيكتب كود»** — هو **هارنس** (حلقة وكيل) حوالين الموديل: أدوات + سياق
   مُدار + صلاحيات + تحقق. الموديل يقرأ، ينفّذ، يتأكد، ويكرّر.
2. قوته الحقيقية مش في الأدوات نفسها (كلنا عندنا `read`/`edit`/`bash`) — قوته في
   **الطبقة اللي حوالين الأدوات**: صلاحيات متدرّجة، hooks حتمية، وكلاء فرعيين،
   ذاكرة مشروع، و«رجوع بالزمن» (rewind).
3. أكبر ضعفه: **التكلفة والحدود** (ناس بتقول «أحسن أداة استخدمتها في الـ45 دقيقة اللي
   أقدر أستخدمها فيها») + **تدهور السياق** في الجلسات الطويلة + إنه **طرفية فقط**.
4. المهارات (Skills) بقت **معيار مفتوح** (`SKILL.md` + `name`/`description` + تحميل
   تدريجي) — وده اللي إحنا بدأناه في المرحلة 8، بس ناقصنا نصفه الثاني.
5. **أهم 5 حاجات ناقصة عندنا** (تفصيلها في §9): معاينة التعديل قبل تنفيذه + رجوع (undo)،
   ملف قواعد للمشروع (`AURA.md`)، وكيل فرعي لعزل السياق، hooks/قواعد حتمية،
   وخطة-قبل-التنفيذ + عدّاد سياق وتكلفة.
6. إحنا **مش** منافس ليه ومش المفروض نبقى: هو للكمبيوتر والمطوّر، إحنا للموبايل والمستخدم
   العادي. لكن **المبادئ** اللي خلت الناس تحبه تنفعنا حرفياً.

## 2. إزاي بيشتغل فعلاً

### 2.1 الحلقة (agentic loop)

```
طلب المستخدم → يجمع سياق (قراءة/بحث) → ياخد إجراء (تعديل/تشغيل) → يتحقق (اختبارات/أخطاء) → يكرّر
```

أدواته بتتقسم 5 عائلات: ملفات، بحث، تنفيذ (Bash/PowerShell)، ويب (بحث/جلب)، وذكاء كود (LSP).
وفوقهم أدوات تنسيق: `Agent` (وكيل فرعي)، `AskUserQuestion`، `TodoWrite`،
`EnterPlanMode`/`ExitPlanMode`، `EnterWorktree`، `CronCreate`، `Monitor`، `Artifact`،
`NotebookEdit`، `Skill`… (أكثر من 25 أداة في المرجع الرسمي).

### 2.2 حاجات حوالين الحلقة (ودي الأهم)

| الطبقة | بتعمل إيه | عندنا؟ |
|---|---|---|
| **Permission modes** | 6 أوضاع: Manual / acceptEdits / plan / auto (مصنّف يقرر) / dontAsk / bypass | لأ — مفتاح واحد تشغيل/إيقاف |
| **Hooks** | سكربتات حتمية على أحداث: `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Notification`, `Stop`, `SubagentStop`, `FileChanged` | لأ — عندنا قائمة منع ثابتة في `shell` بس |
| **Subagents** | وكيل بسياق مستقل وأدوات محددّة وموديل أرخص، يرجع ملخص بس | لأ |
| **CLAUDE.md + auto memory** | ملف قواعد كل جلسة + ملاحظات الموديل نفسه (أول 200 سطر/25KB) | لأ — عندنا ملخص محادثة قديمة بس |
| **Skills** | تعليمات تُحمّل عند الحاجة (تحميل تدريجي 3 مستويات) | ✅ موجود (نص فقط) |
| **MCP** | توصيل أدوات خارجية (قواعد بيانات، Slack، متصفح…) | لأ |
| **Plugins + marketplace** | حزمة (skills + hooks + agents + MCP) تُثبّت بأمر | لأ |
| **/rewind + checkpoints** | رجوع للمحادثة والملفات لحظة معينة | لأ (مفيش undo خالص) |
| **Auto-compaction + prompt caching + /usage** | ضغط المحادثة قبل امتلاء السياق + توفير كاش + عدّاد تكلفة | جزئياً: عندنا تقليص وتوكنز، مش تلخيص ولا تكلفة |
| **Worktrees / agent teams / cloud / Remote Control** | تشغيل متوازي وعن بُعد | لأ (وغالباً مش محتاجينه) |

## 4. المهارات بالتفصيل (المعيار المفتوح)

**الشكل:** مجلد + `SKILL.md` بـ YAML frontmatter ثم Markdown.

| الحقل | إلزامي؟ | القاعدة |
|---|---|---|
| `name` | ✅ | حروف صغيرة وأرقام وشُرَط، ≤64، ويطابق اسم المجلد |
| `description` | ✅ | ≤1024، يقول **إيه** و**إمتى** (ده المُشغِّل) |
| `allowed-tools` | اختياري | أدوات مسموحة مسبقاً (تجريبي) |
| `license` / `compatibility` / `metadata` | اختياري | ترخيص، متطلبات بيئة، بيانات إضافية |

**التحميل التدريجي (progressive disclosure)** — ودي الفكرة العبقرية:
1. الميتاداتا (~100 توكن) لكل المهارات، دايمة في الـ prompt.
2. نص `SKILL.md` (أقل من 5000 توكن مفضّل) لما المهارة تُفعّل بس.
3. `scripts/`, `references/`, `assets/` — عند الطلب فقط.

**الـ 19 مهارة الرسمية:** `docx` `pdf` `pptx` `xlsx` (المستندات) · `canvas-design`
`algorithmic-art` `brand-guidelines` `theme-factory` `slack-gif-creator` (تصميم) ·
`frontend-design` `web-artifacts-builder` `webapp-testing` `mcp-builder` `claude-api`
`skill-creator` (تقنية) · `doc-coauthoring` `internal-comms` `academy-guide`
`discernment-nudge` (تواصل/إرشاد).

**مهارات مدمجة في البرنامج نفسه:** `/code-review`, `/debug`, `/run`, `/verify`,
`/loop`, `/doctor`, `/claude-api`, `/simplify`… بعضها Claude يستدعيها لوحده، وبعضها
إنت بس اللي تستدعيها (`disable-model-invocation`).

**إضافات Claude Code فوق المعيار:** تحكم مين يستدعي المهارة، تشغيل المهارة **جوّه وكيل
فرعي** (`context: fork`)، وحقن سياق حيّ بسطر `` !`git diff HEAD` `` — يعني المهارة توصل
للموديل والفرق (diff) محقون فيها أصلاً.

## 8. مميزاتنا وعيوبنا بصراحة

**مميزاتنا (اللي لازم نحافظ عليها):**
1. إحنا على التليفون — السياق اللي Claude Code بيفتقده (صور، تطبيقات، مشاركة ملف من أي تطبيق).
2. **حرية المزوّد**: مفيش قفل على شركة، والمفتاح على الجهاز.
3. **عربي حقيقي** (RTL + مفاتيح ترجمة كاملة) — مفيش منافس بيعمل ده.
4. شفافية الأخطاء: بنقول سبب الخطأ الحقيقي مش «حصل خطأ».
5. أدوات الموبايل: فتح تطبيقات، بحث، مشاركة، توليد صور.
6. كود مقروء ومختبَر — نقدر نطوّر بسرعة.

**عيوبنا (اللي لازم نتعلّم منها):**
1. **بنعدّل الملفات من غير معاينة** — أخطر حاجة. المستخدم مالوش كلمة قبل التغيير.
2. **مفيش رجوع** (undo) للملفات ولا للمحادثة.
3. **مفيش ذاكرة مشروع**: كل جلسة تبدأ من الصفر، ومفيش مكان يكتب فيه «قواعد بيتي».
4. **مفيش وكلاء فرعيين** → قراءة 20 ملف بتحرق السياق كله في المحادثة الرئيسية.
5. **مفيش hooks/قواعد حتمية**: «متلمسش مجلد كذا» مجرد كلام في الـ prompt.
6. **مفيش وضع خطة بموافقة**: عندنا «مراجعة قبل الرد» اختياري، مش بوابة موافقة.
7. **مفيش عدّاد سياق** («فاضل كام في نافذة الموديل») ولا تكلفة بالدولار.
8. **مفيش تلخيص للسياق** — بنقصّ، وده بيفقد القرارات القديمة.
9. **مفيش MCP** → مفيش تكامل مع أدوات المستخدم (Notion, Drive, Slack…).
10. **المهارات نص بس** — مفيش `scripts/` ولا `references/` ولا `allowed-tools`.
